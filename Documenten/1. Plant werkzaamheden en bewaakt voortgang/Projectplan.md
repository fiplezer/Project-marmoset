# Projectplan

## Afspraken

### Code schrijven
- Graag **opmerkingen/comments** bij code neerzetten ook al is het voor jou
logisch, zodat iedereen het snapt.
- Voor public gebruiken wij **PascalCase**. Voorbeeld: altijd starten met een hoofdletter
(Grond of KaleKippenSoep).
- Private **lower camelCase**. Voorbeeld: altijd starten met een lage letter (grond of
kaleKippenSoep).
- Voor de git gerbuiken wijn **kebab-case**. Voorbeeld: woorden met een streepje er tussen en
kleine letters (grond of kale-kippen-soep).
- Gebruik maken van **Headers**, zodat het in de editor ook overzichtelijk is.

### Github
- Kebab gebruiken.
- De branches formatteren met de issue nummer en naam (05/ui-rework of
10/main-menu-toevoegen).
- Push niet direct naar main, maar naar een test branch.
- Laat je werk eerst nakijken voordat je merged.
- Maak overzichtelijke mappen.
- Git issues is een user story en sub issues leggen uit hoe je de user story kan
realiseren.  
- Gebruik de Nederlandse taal.
- Vul je deadlines in.

### Met elkaar omgaan
- Zit bij elkaar.
- Respecteer elkaar, mocht er iets zijn waar je het oneens mee bent, ga geen ruzie
maken, maar overleg dit met elkaar.
- CC elkaar in mails.
- Vraag elkaar om hulp, blijf dus niet te lang bij een probleem hangen
Scrum leider schema.
